# แผนที่โดมิโน (Fan-out map) — ค่าไหนแตกไปกี่ทาง

> **ใช้ตอนไหน:** ก่อนแก้ค่าใดๆ ใน audio path ให้เปิดไฟล์นี้หาค่านั้นก่อน
> ถ้ามันอยู่ในตารางแปลว่า **แก้แล้วมีอย่างอื่นขยับด้วย** — ต้องวัดทุกช่องในคอลัมน์ "พังได้"

## ทำไมต้องมีไฟล์นี้

ความพลาดทุกครั้งในโปรเจกต์นี้มีรูปแบบเดียวกัน:
**แก้ค่าที่คุมหลายพฤติกรรม แล้ววัดผลแค่พฤติกรรมที่กำลังแก้**

| แก้เพื่อ | ที่พังไปด้วย | เจอตอน |
|---|---|---|
| ใส่ deadband กันกระตุก | รอบนิ่งสนิท ไม่หายใจ | เจ้าของทัก |
| ย้ายเกนหนี limiter pumping | ไปเจอ clipping แทน | วัดทีหลัง |
| ใส่เส้นโค้งแก้เร่งเบาเงียบ | คันเร่งไวเกิน | เจ้าของทัก |
| ยกความดัง 3 ตัวพร้อมกัน | limiter ปั๊มหนัก | เจ้าของทัก |
| เพิ่ม bass 50→100 (ผู้ใช้หมุนเอง) | หลุด headroom → กระตุก | เจ้าของทัก |

**สามในห้าครั้ง เจ้าของเป็นคนเจอ ไม่ใช่ผม** — นั่นคือปัญหาที่ไฟล์นี้แก้

---

## 1. `accelLoad` — ค่าเดียว ผู้อ่าน 12 จุด 3 พฤติกรรม

`js/crank-audio.js` บรรทัด 785–954 · **ค่าที่อันตรายที่สุดในไฟล์**

| กลุ่ม | ผู้อ่าน | ควบคุม |
|---|---|---|
| **รอบไปไหน** | `rpmInGear` (883) · `rpmLambda` (894) · `resolveGear` ผ่าน `accelRaw` (856) | ตำแหน่งรอบ ความเร็วที่รอบไล่ จุดเปลี่ยนเกียร์ |
| **สถานะการขับ** | `driveState` pull/overrun (931, 935) · `_overrunLatch` · gate เปลี่ยนเกียร์ (840) · จอดนิ่ง (846) | จังหวะตัด overrun เสียง shift |
| **ดังแค่ไหน** | `load` (815, 917, 919) · `effTarget` (942) | ความดัง dynamic volume |

**ปัจจุบันแยกแล้ว** — `accelLoad` (ดิบ) ไปทางรอบ+สถานะ, `accelVoice = accelLoad^0.65` (806) ไปทางความดังเท่านั้น

> **กฎ:** จะแตะเส้นโค้ง/deadband/smoothing ของคันเร่ง **ต้องบอกให้ได้ก่อนว่าใส่ทางไหน**
> ใส่ผิดทาง = รอบกระตุกหรือความดังเพี้ยน ใส่ทั้งสองทาง = ได้ทั้งสองอาการ

## 2. เกน 4 ตัวต่ออนุกรม → headroom ก้อนเดียว

ทั้งสี่ตัวคูณกันก่อนเข้า limiter **ขยับตัวไหนก็เปลี่ยนสิ่งที่ limiter เจอเท่ากัน**

| ค่า | อยู่ที่ | บรรทัด |
|---|---|---|
| `_outputTrim` | `compressor.gain` | 596, 1222 |
| ชดเชย bass shelf | `compressor.gain` (ตัวเดียวกัน) | 1222 |
| `_makeup × _masterScale` | `makeup.gain` | 661 |
| `dynDb` / `dynCeiling` | `dynGain` | 93, 1152, 1157 |

**อาการเมื่อพลาด — แยกให้ออก เพราะแก้คนละทาง:**

- **ปั๊ม (pumping)** — `limiter.reduction` ค้างลึกกว่า −2.5 dB โดยเฉลี่ย
  → limiter กำลังทำหน้าที่ปรับระดับ ไม่ใช่กันพีค **ลดเกนก่อน limiter**
- **แตก (clipping)** — สัดส่วนตัวอย่างที่เข้า brick wall เกิน 1%
  → เกนอยู่**หลัง** limiter หรือสูงเกินจนกำแพงต้องรับเอง **ย้ายเกนมาก่อน limiter**

ทั้งสองมาจากรากเดียวกันคือ headroom แต่ **แก้ทางตรงข้ามกัน** — วัดก่อนเดา

## 3. `_bass` — ปุ่มของผู้ใช้ที่ขยับ headroom

บรรทัด 1216–1222 · `shelfDb = (bass − 0.5) × 10` → **±5 dB**

ปุ่มนี้อยู่ในมือผู้ใช้ ไม่ใช่ในโปรไฟล์ **หมุนสุด = ยัดเพิ่มอีก 5 dB เข้าเส้นทางเดียวกับข้อ 2**
ตอนนี้ชดเชยด้วย `compDb = −shelfDb × 0.6` ที่ `compressor.gain`

> **กฎ:** ปรับ gain staging เสร็จ **ต้องวัดที่ bass 0 / 50 / 100 ทั้งสามค่า**
> จูนที่ 50 อย่างเดียวแล้วผู้ใช้หมุนไป 100 = กระตุกที่เราไม่เคยเห็น (เกิดขึ้นจริงมาแล้ว)

## 4. ค่าที่ระบบใช้ร่วมกันทุกเครื่องยนต์

**แตะแล้วกระทบทุกโปรไฟล์ ไม่ใช่แค่ตัวที่กำลังแก้**

| ไฟล์ | ค่า | ใครใช้ |
|---|---|---|
| `js/gearbox.js` | `GEAR_VMAX` `UP_AT` `DOWN_AT` | ทุกเครื่องยนต์ที่มีเกียร์ |
| `js/vehicle-physics.js` | `accelKmhps` | ทุกเครื่องยนต์ (เคยเป็นบั๊กระดับแอป) |
| `js/geolocation.js` | deadband จอดนิ่ง | ทุกเครื่องยนต์ |

> **กฎ:** แก้สามไฟล์นี้ = ต้องรัน bench **ทุกโปรไฟล์** ไม่ใช่ตัวที่กำลังแก้
